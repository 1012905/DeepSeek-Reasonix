## Issue #14554 — 复制含图片的 prompt 后，图片与内部路径文本同时出现

**背景**：用户给出 GitHub issue 链接 https://github.com/esengine/DeepSeek-Reasonix/issues/14554，
要求处理。issue 报告 Reasonix Studio 中，复制一条带图片的用户消息再粘贴，`.reasonix/attachments/clipboard-*.png`
这条内部存储路径会作为纯文本同时出现在输入框/消息正文里，同一张图被表达两次。

**根因（已对照源码核实，报告分析准确）**：
一张图片走了两条互不知情的通道——
- 通道 A（正常）：`internal/session/control/attachments_wire.go` `StoredAttachments` → `internal/frontend/serve/history.go:86`
  → 前端 `UserCard.tsx` 渲染 `.user-images` 缩略图。
- 通道 B（冗余）：`desktop/frontend-next/src/ui/Composer.tsx` `send()` 把每个附件的 `ref`（`@`+路径）拼进正文，
  于是 `item.text` 里含 `@.reasonix/attachments/...`；`UserCard.tsx` 的 `<CopyButton text={item.text}/>` 复制的就是它，
  粘贴后路径以文字落回输入框，再被 `internal/session/control/refs.go` 的 `classifyRef` 命中解析成图片。

**关键设计约束（报告未点明，决定了修法）**：
正文里的 `@path` 是**故意**保留的——回合解析（`classifyRef`/`detectRefsMode`）靠它把图片解析回像素，
CLI 与其它客户端也依赖它。所以 issue 建议的「方向1（正文不承载路径）」会破坏 CLI 兼容并推翻现有 6+ 条测试断言。
因此采用**方向2：展示层与复制层剥离 token，存储格式完全不动**。

**改动**（纯前端，未动 Go 端持久化/解析逻辑）：
- 新增 `desktop/frontend-next/src/ui/attachrefs.ts`：`stripAttachmentRefs(text, attachments?, keep?)`
  剥掉已被 `attachments` 覆盖的 `@.reasonix/attachments/...` token；`keep` 用于保留加载失败的图片的引用作为兜底。
- `desktop/frontend-next/src/ui/cards/UserCard.tsx`：
  - 新增 `failedImages` state，`SavedImage` 上报 `onError`/`onLoad`；
  - 展示文本用 `displayText`（有 port 时剥离；缩略图加载失败时保留 token 兜底）；
  - `CopyButton` 改用 `copyText`（始终剥离），使复制→粘贴不再把裸路径插回输入框；
  - 「改写」编辑框与 rewind 仍用原始 `item.text`（重发语义需要 token）。
- 测试同步更新：`user-images.interaction.test.tsx`（去掉 "keeps the reference" 旧断言、复制断言改为剥离后的文本）、
  `image-preview.interaction.test.tsx:42`（`getByText(item.text)` → `getByText("Read this")`）。

**验证**：`vitest run src/ui/user-images.interaction.test.tsx` 13/13 通过；`tsc --noEmit` 无错误；
前端全量 `vitest run` 跑通。

**已知取舍 / 后续项（未做，需用户决策）**：
- 复制载荷不再含路径 → 复制到新会话时**图片不再随路径复活**（图片字节本就不在剪贴板上）。
  恢复图片随行需二选一：(a) issue 方向3——`CopyButton` 额外写 `image/png` 的 `ClipboardItem`；
  (b) 新增 host 端接口把**已存路径**解析回 attachment，让 Composer 在粘贴时把路径 token 转成附件 chip
  （目前 `port.attach()` 只能上传新字节，没有「按已有路径取 ref/image」的能力）。
- Go 端 `sessionstore.UserSaidText` / `StripTransientUserBlocks` **刻意未动**：它们管持久化正文，
  剥离路径会毁掉回合解析所需的 token。

**环境备注**：`desktop/frontend-next` 用 pnpm（`pnpm-lock.yaml`）；首次 `pnpm install --frozen-lockfile`
会报 `ERR_PNPM_IGNORED_BUILDS`（esbuild 构建脚本被忽略），但 esbuild 仍可用，vitest 正常跑。

## 复制按钮交互增强（分割按钮 + 路径标注 + 粘贴还原）

直接单击按钮本体执行「全部复制」；「全部复制」写入图片路径标注 + 文本，标注格式
工作文件夹下图片写 `@//a.jpg/`、指定路径图片写 `@//c/:\a.jpg`；粘贴后输入框显示图片、
发送后消息正文不得再出现路径；剪贴板失败要明确报错 + 降级，图片加载失败降级为仅复制文字。

**路径标注格式（本次确立的规则，可逆）**：
- 相对（工作文件夹下）路径 → `@//` + 路径 + `/`，如 `a.jpg` → `@//a.jpg/`
- 绝对（指定路径）路径 → `@//` + 路径且盘符冒号写成 `/:`，如 `c:/a.jpg` → `@//c/:\a.jpg`
- 反解：含 `/:` → 绝对（`/:` 还原成 `:`）；否则去掉结尾 `/` → 相对。
- 实现在 `desktop/frontend-next/src/ui/imagepaths.ts`（`annotateImagePath` / `parseImagePaths` / `resolveImagePath`），
  单点收敛，用户若要改口径只改这一个文件。

- 新增 `ui/CopyImagesButton.tsx`：分割按钮（本体=全部复制，箭头=Picker 菜单）。
  复用 `ui/Menu.tsx` 的 `Picker`——它已具备浮层定位、外部点击关闭、ESC 关闭+焦点归位、
  方向键导航、选中后关闭并把焦点还给触发按钮。
- 改 `ui/CopyButton.tsx` 的 `copyText`：现代 API 失败/超时（1.5s）→ 回退 `execCommand` →
  仍失败 → 抛「剪贴板不可用，请手动复制：{text}」并保留 `cause`（不再静默失败）。
  **这是行为契约变更**：旧测试断言原始错误直接抛出，已按新契约更新 `CopyButton.test.tsx`。
- 改 `ui/cards/UserCard.tsx`：有图时用分割按钮，无图仍用普通 CopyButton；
  失败/降级提示渲染为 `.copy-note`（role=status）。

  `port.attach()` 存为本轮附件（所以正文只剩图片与文字，路径不进消息）；

## 工作区外的图片：后端读取能力

**需求**：「工作区外的图片实现后端」——让工作区之外的图片也能被读出来（粘贴外部路径时变成真图片，而不是路径 token）。

**安全模型（关键）**：命名一个路径 ≠ 获得授权。只有**已有的授权**才能读到工作区外的文件：
- `Controller.ReadableExtraRoots()`——用户级「授予本工作区的额外根目录」（存在用户 home，仓库自己加不了；`VetReadableRoot` 复核）。
- `externalFolders` 注册表——本会话里用户拖进来的文件夹/文件（session 级）。
不在这两处的绝对路径一律拒绝——所以剪贴板里的路径无法变成读磁盘的通道。

**后端改动**：
- 新增 `internal/session/control/external_read.go`：
  `Controller.ReadableExternalPath(path) (root, rel string, ok bool)`——回答「这个工作区外的路径能在哪个根下读到」；
  工作区内的路径不算外部；相对路径不算；带盘符/UNC 的按绝对路径处理。
- `external_folders.go` 增 `readableUnder(abs)`：注册的是**文件**时，基目录取其所在目录、相对路径取文件名（只授权那一个文件，不授权同目录其他文件）。
- `port.go` 增 `ExternalReads` 接口组并并入 `SessionAPI`（只有 `*Controller` 是具体实现者，其它 mock 都是内嵌接口，加方法不破坏）。
- `internal/frontend/serve/workspace_image.go`：`GET /workspace/image` 的 `path` 若是绝对路径 → 走 `externalImage()`；
  先查扩展名是不是图片类型，再查授权，授权不过一律 403 `workspace.root_not_granted`（不给读）。
  抽出 `writeImage()` 复用 CSP sandbox / nosniff 头。

**前端改动**（`Composer.tsx` 的 `takeImages`）：
- 路径统一交给宿主读：`readImage(port.workspaceImageURL(path))`，相对/绝对都试。
- 读得到 → `attach()` 存为本轮附件（所以正文里不再出现路径）。
- 读不到且是绝对路径 → 报错「工作区外的图片无法读取：{path}」，**且不调用 dropRefs**（不制造授权）。
- 读不到的相对路径 → 仍走原来的就地引用。

**已知缺口（未做）**：转录本仍不上报**外部图片**（`StoredAttachments` 只收 `.reasonix/attachments/` 下的图），
所以「全部复制」目前只会写工作区内的路径（`@//...` 相对形式）；`@//c/:\a.jpg` 这种指定路径形式需要
转录本携带外部图片的绝对路径（还要定：原生反斜杠写法 `c:/a.jpg` 还是归一化的 `c:/a.jpg`）。
另外外部图片就地引用时正文里仍是 `__reasonix_external_folder/...` token，`stripAttachmentRefs` 只剥 `.reasonix/attachments/` 的。

**环境限制**：本机 Go module proxy 不可达（Bad Gateway），`internal/session/control` 的测试二进制依赖
`go.uber.org/goleak` 拉不下来 → 该包测试跑不了（临时把 `main_test.go` 移开跑完新测试后已还原）；
`internal/frontend/serve` 的测试可跑 ✓。

## 一并处理：转录本上报外部图片 + 剥离就地引用 token（收尾 #14554）

**用户指令**：「一并处理」——把上一段落里「已知缺口」的两件事补齐：
1. 「全部复制」目前只写工作区内路径：转录本 `StoredAttachments` 只收 `.reasonix/attachments/` 下的图，
   外部图片（`@//c/:\a.jpg` 形式）没有生产者 → 需要转录本携带外部图片的**绝对路径**。
2. 外部图片就地引用时正文里仍是 `__reasonix_external_folder/...` token，`stripAttachmentRefs` 只剥 `.reasonix/attachments/` 的；
   要求一并处理，不露 token。

**路径分隔符决策**：沿用仓库既有约定——宿主对外一律给归一化的 `filepath.ToSlash` 形式（如 `c:/a.jpg`），
所以 `StoredAttachments` 上报的外部图片 `Path` 用**正斜杠绝对路径**；标注/反解在 `imagepaths.ts` 统一处理，
`c:\a.jpg`（原生反斜杠）与 `c:/a.jpg`（归一化）都能反解回原绝对路径。

**后端改动**：
- `contract/event/attachment.go`：`Attachment` 增 `Ref string`；`contract/eventwire/attachment.go`：`Attachment` 增 `Ref`、
  `ToWireAttachments` 同步拷贝；前端 `port/wire.ts` `StoredAttachment` 增 `ref?: string`。
- `internal/session/control/attachments_wire.go`：重写 `StoredAttachments`——
  工作文件夹图仍报 `.reasonix/attachments/...` 相对路径（Ref=""）；
  **外部图**（`r.baseDir != ""` 且是图片）报绝对路径 `Path`（ToSlash 归一化，供粘贴回读）+ `Ref = r.raw`（不透明 token，供前端隐藏）。
  仅当文件仍在时才上报（`os.Stat` 是常规文件）。
- 新增测试 `TestStoredAttachmentsCarryExternalImagesByAbsolutePath`（control 包，需临时移开 `main_test.go` 跑，已还原）。

**前端改动**：
- `ui/attachrefs.ts`：`AttachmentPath` 增 `ref?`；`stripAttachmentRefs` 增 `externalRefRe = /@__reasonix_external_folder\/[^\s]*/g`，
  把命中图片附件的 token 一并剥掉（外部 token 是不透明哈希，加载失败也剥——"不可用"框比哈希更说明问题；
  工作文件夹 token 仍走原 keep-on-failure 逻辑）。
- `ui/imagepaths.ts`：修 POSIX 绝对路径圆转。原实现 `@//` + `/folder/x.png` = `@///folder/x.png` 反解会丢根；
  改为反解时若 body 以 `/` 开头则整段返回（即路径本身）。同步修 `imagePathToken` 正则顺序，
  让 POSIX 形态（`@///...`）排在相对形态之前，避免内部斜杠被相对规则的尾斜杠吞掉。
  绝对盘符路径 `c:\a.jpg → @//c/:\a.jpg`、相对 `a.jpg → @//a.jpg/` 行为不变（有测试守护）。
- `ui/copy-images.interaction.test.tsx`：增「外部图片就地引用」用例，断言「全部复制」写出 `@//c/:/folder/outside.png 请看这张图`、
  气泡按绝对路径取缩略图且不露 token。新增 `ui/imagepaths.test.ts`、`ui/attachrefs.test.ts` 单元用例。
